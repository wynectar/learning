## 🔥你的日常 AI 工作流是什么？

```text
需求分析 → Context 构建 → AI 生成代码 → 质量保障 → 持续优化
```

- 页面结构：导航、列表、表单、弹窗、分页

- 交互逻辑：加载、空状态、报错、表单校验、权限
- 接口字段：入参、出参、默认值、枚举

### 2. Context 构建

- 维护项目 Rule 文件（代码规范、架构约束）
- 配置 MCP 服务（提供项目特定上下文）
- 沉淀 Skills（常见任务的最佳实践）
- 持续更新 README 和 Onboarding 文档

::: tip
- 项目技术栈、目录结构
- 已有的封装：axios、请求拦截、全局组件、工具函数
- 代码规范：命名、文件夹分层、TS 类型写法
- 现有同类组件 / 页面参考代码
:::


### 3. AI 生成代码

- UI to Code：设计稿直接生成组件代码
- 组件生成：可复用组件批量生产
- 逻辑实现：业务逻辑 + 状态管理
- 测试生成：单元测试 + 集成测试

### 4. 质量保障（人工 + AI 双重校验）

- 静态检查：ESLint + TypeScript + Prettier
- 自动测试：Jest + React Testing Library
- CI Pipeline：自动化流水线
- Code Review：AI 辅助 + 人工 Review 结合

::: tip
- 代码规范：AI 检查命名、缩进、冗余代码
- 类型安全：TS 类型补全、缺失字段补充
- 交互边界：空数据、加载中、异常兜底、防抖节流
- 样式兼容：移动端、不同屏幕、浏览器适配
- 性能检查：不必要渲染、重复请求、大列表优化
- 自测联调：跑通流程、对接后端接口
:::

### 5. 持续优化

- Code Review 反馈：收集团队对 AI 生成代码的反馈
- 线上监控：监控 AI 生成代码的运行表现

## 🔥知道哪些 Cursor 使用技巧？
Cursor 是基于 VS Code 的 AI 编辑器，核心优势在于**深度上下文理解**和**@指令系统**。掌握以下技巧，能大幅减少重复劳动、避免 AI 幻觉、提升代码质量。

### 核心快捷键
- **Ctrl / Cmd + K**：AI 内联编辑（生成/修改/解释代码）

- **Ctrl / Cmd + L**：将选中代码加入 AI 对话
- **Ctrl / Cmd + I**：打开全局聊天（Composer 模式）

- **Tab**：接受 AI 单行/多行补全
- **Ctrl / Cmd + Shift + L**：打开独立聊天窗口
- **Alt + \**：手动触发 AI 补全

### @指令：精准上下文（最强大技巧）
在聊天框输入 `@`，可精准指定 AI 的参考范围，**彻底解决幻觉**：
- **@Code**：引用选中代码（选代码后输入）
- **@FileName**：引用特定文件（如 `@App.tsx`）
- **@FolderName**：引用整个目录（如 `@src/hooks`）
- **@Codebase**：全局搜索整个项目

- **@Web**：联网搜索最新信息

- **@Docs**：引用内置库文档（如 `@Docs React`）

**示例**：
```
@App.tsx @useUser.ts 优化这两个文件的类型定义，消除any
```

### 3种工作模式（减少返工）
- **Ask（默认）**：直接回答，快速生成
- **Plan（Shift+Tab）**：先出方案，你确认后再写代码（复杂需求首选）

- **Agent**：自动执行多步骤任务（重构、建项目）

### Rules：团队规范固化（一劳永逸）
在项目根目录建 `.cursor` 文件夹，写 `rules.md`：
```markdown
# 项目规则
- 技术栈：React 18 + TypeScript + Tailwind
- 命名：小驼峰，组件用大驼峰
- 必须加 JSDoc 注释
- 禁用 var，优先 const
- 错误处理：try/catch + 自定义Error
```
AI 生成代码时**自动遵守**，无需反复提醒。

### 高效开发流程
1. **代码解释/注释**
选中代码 → `Ctrl+K` → "解释作用" / "加详细注释"
2. **Bug 修复**
选中报错代码 → `Ctrl+L` → "修复bug，处理边界"
3. **重构**
选中函数 → `Ctrl+K` → "拆分为小函数，加类型，优化性能"
4. **生成测试**
`@utils.ts` → "生成单元测试（Jest），覆盖正常/异常"
5. **Plan 模式做复杂页面**
`Shift+Tab` → "做用户列表（增删改查），React+TS+Antd" → 确认方案 → 生成

### 避坑技巧
- **分阶段生成**：先架构 → 再组件 → 最后样式
- **Checkpoint 回滚**：AI改坏代码 → 用Checkpoint一键恢复
- **控制上下文**：少用全局对话，多用 `@文件` 缩小范围
- **提示词精准**：指定技术栈、功能、规范、边界场景
- **强制校验**：生成后要求"检查类型、空值、异常、内存泄漏"

### 进阶效率神器
- **Notepad**：侧边栏记事本，存提示词/上下文，`@` 调用
- **@Git**：对比分支差异，检查MR风险
- **终端AI**：终端里 `Ctrl+K`，自然语言转命令
- **图片转代码**：拖设计图到聊天 → "转React页面，Tailwind样式"

## 🔥Skills 了解吗？你的项目用到了吗？

**Skills = 预制好的专业AI角色 + 固定工作流 + 编码规范模板**

### 常用内置 Skills 有哪些
1. **Code Review**：自动帮你做代码评审、找隐患、给优化建议
2. **Refactor Code**：一键重构、拆组件、去冗余、优化依赖
3. **Write Unit Test**：按项目规范自动生成单测用例
4. **Fix Bug**：智能定位报错、分析根因、给出修复方案
5. **TypeScript Expert**：补全类型、消除 any、修正接口类型
6. **Frontend Engineer / React / Vue Skill**：前端专属编码风格、组件拆分规范
7. **Documentation**：生成注释、接口文档、README

### 项目里有没有用到？

1. 用 **React/TypeScript 专属 Skill**
固定遵循项目 ESLint、组件命名、TS 类型规范，不用每次重复约束 AI，生成代码风格统一。

2. 日常用 **Refactor + Code Review Skill**
批量重构老代码、JS 转 TS、拆分臃肿组件，同时自动做规范和隐患检查，减少人工 Review 工作量。

3. 用 **Unit Test Skill**
工具函数、通用组件直接调用技能生成单测，统一用例风格。

4. 配合 `.cursorrules` + Skills 联动
Rules 管项目私有规范，Skills 管通用专业能力，**双重约束**，AI 产出更稳、更少幻觉、更贴合团队标准。

::: details `通用前端工程规范（日常开发默认用）` Skill
```text 
你是资深 React + TypeScript 前端工程师，所有代码生成、修改、重构必须严格遵守以下规则：

1. 技术栈：React18 + Hooks + TypeScript，只用函数组件，不写类组件。
2. TS 严格模式：绝不出现隐式 any，必须定义完整接口、类型，公共类型抽离单独管理。
3. 组件拆分：容器组件负责逻辑和请求，UI 组件只负责渲染，单一职责。
4. 命名规范：语义化英文命名，组件大驼峰、变量方法小驼峰，禁用拼音和无意义缩写。
5. 状态与请求：接口请求必须处理 loading、空数据、异常报错、无权限边界状态；提交和搜索加防抖，防重复请求。
6. 生命周期规范：定时器、事件监听、订阅，组件卸载必须销毁，杜绝内存泄漏。
7. 异步写法：全部用 try/catch 捕获异常，不裸写 Promise。
8. 代码规范：遵循 ESLint、Prettier，无冗余导入、无用变量、死代码；useEffect 依赖项严格补齐。
9. 样式方案：优先 Tailwind / CSS Module，禁止全局样式污染，布局做好响应式适配。
10. 输出要求：只生成可直接落地的规范代码，关键逻辑加注释，如有旧代码自动兼容项目现有风格，不自创写法。
```
:::

::: details `代码重构专用` Skill
```text 
你是专业前端代码重构专家，接手任何组件、页面、工具函数，都按以下标准重构优化：

1. 结构优化
- 超大组件拆分为：容器组件 + 子UI组件 + 自定义Hooks
- 业务逻辑和视图彻底分离，减少单文件代码行数

2. 逻辑精简
- 剔除冗余变量、无效导入、死代码、重复逻辑
- 简化嵌套if/else，优先卫住写法
- 抽离重复业务逻辑到公共 hooks 或 utils

3. TypeScript 优化
- 补全缺失类型，消除所有 any
- 抽离复用 interface/type，统一管理
- 修正类型不匹配、字段缺失问题

4. React 语法优化
- 修正 useEffect 依赖项，修复死循环、不更新问题
- 优化不必要渲染，合理拆分组件粒度
- 清理未销毁定时器、事件监听，修复内存泄漏

5. 规范与健壮性
- 统一命名、格式、代码风格，符合 ESLint
- 补齐边界状态：loading、空数据、异常兜底
- 异步全部加 try/catch，增加容错能力

6. 输出要求
重构完成后列出：优化点、拆分思路、潜在风险说明，保证功能不变、质量提升、可直接上线。
```
:::

::: details `TypeScript 类型专项` Skill
```text 
你是 TypeScript 类型专家，专门负责类型补全、纠错、重构、规范治理，严格遵守：

1. 绝不允许隐式 any、滥用 any，所有变量、入参、出参必须有明确类型定义。
2. 接口数据优先用 interface，通用枚举、常量、公共类型统一抽离。
3. 自动推导缺失字段、嵌套结构，补全后端返回完整TS类型。
4. 优化类型写法：简化交叉类型、冗余泛型，让类型简洁易维护。
5. 把 JS 代码完整转标准 TS，补齐所有参数、返回值、对象结构类型。
6. 识别类型隐患：可选符滥用、类型范围过大、字段可选必选不合理，并自动修复。
7. 输出格式：先给出抽离的公共类型，再改写业务代码，标注改动点和原因。
```

## 🍎团队如何统一 AI 工具配置？（Rule 文件、MCP 服务等）

- 统一编辑器 & AI 工具栈
- 统一规则约束：Rule /.cursorrules/ 全局 Prompt
- 统一项目上下文：MCP 服务、项目基线库
- 统一质检 & 交付标准：模板 + 工程化门禁

### 1. 什么是 Rule 文件

放在项目根目录，AI 工具自动读取，全局强制约束所有 AI 生成代码风格、规范、写法.

::: tip 常用文件
- `.cursorrules` （Cursor 专用，最强）
- `.aicoderules` / `.rules` （通用 AI 编程规则）
- VS Code 共享配置 `.vscode/settings.json` + 全局 AI 约束 Prompt
:::

::: tip 团队强制规范
- 技术栈：React/Vue3 + TS 必写、禁用隐式 any
- 代码规范：遵循 ESLint/Prettier、命名语义化、禁止魔法值
- 组件规范：必须拆分 UI / 业务组件、单一职责
- 交互规范：必须处理 loading / 空数据 / 异常兜底 / 权限
- 样式规范：统一 CSS Module / Tailwind，禁止全局样式污染
- 注释、文件目录结构、Git 提交规范
:::

::: tip 落地方式
- 项目根目录提交 .cursorrules 到 Git
- 新人拉取项目自动生效，AI 自动遵守团队规则
- 不用每个人自己设置，拉代码即统一配置
:::

### 2. 什么是 MCP 服务

Model Context Protocol 模型上下文协议，给团队所有 AI 工具提供统一的项目知识库 & 上下文服务。

- 搭建团队公共上下文库
   - 项目通用 TS 类型、枚举、常量
   - 统一 axios 封装、拦截器、请求范式
   - 公共组件、工具函数、样式规范
   - 高质量业务组件范本（作为 AI 仿写标准）
- MCP 统一注入
   - Cursor / Copilot / Trae 统一关联团队 MCP 服务
   - 所有人 AI 生成代码，共用同一套项目上下文、同一套风格基线
   - 避免 A 写一套、B 写一套，风格混乱
- 价值：新人不用熟悉项目，AI 直接按团队规范生成；老项目改造，AI 自动遵循已有架构，不瞎重构。

## 🍎怎么量化 AI 提效的价值？

### 1. 时间效率类（最硬核、最好量化）
- `单需求开发工时缩短`：同复杂度业务页面/CRUD 组件 **提效 35%～50%**
- `重复编码耗时节省`：样板代码、TS 类型、表单结构、接口请求、基础样式，**60%～75% 重复代码无需手动编写**
- `问题排查耗时下降`：Bug 定位、样式兼容、打包报错、配置问题，**下降 30%～45%**
- `需求交付周期缩短`：整体迭代周期缩短 **20%～30%**

### 2. 产出规模类（看产能）
- 同等人力需求交付量提升
- 个人日/周代码有效产出提升

### 3. 质量损耗类（量化省钱、减少返工）

- `提测缺陷率下降`：提测 Bug 减少 **20%～35%**
- `代码返工率降低`：因不规范、逻辑漏洞、样式问题导致的二次修改次数/工时
- `编码规范合规率提升`：ESLint 错误、隐式 any、命名不规范、目录不规范，从 60%～70% 提升到 **95%+**
- `线上故障率下降`：AI 强约束边界处理、异常捕获，降低低级线上问题。

### 4. 人力&组织价值（可折算成本）
- 节约研发人天
- 新人上手周期压缩
- 减少高阶人力消耗

### 5. 长期工程价值（可量化描述）
- 老项目重构、JS 转 TS、组件拆分周期 **缩短 40%+**
- 技术文档、接口文档、注释编写效率 **提升 60%**
- 团队知识沉淀固化，降低人员流动带来的业务断层成本

### 总结
从五个维度量化 AI 价值：
1. **时间提效**：同复杂度业务开发工时下降 35%~50%，重复编码70%由AI替代；
2. **产能提升**：同等人力下版本需求交付量明显增加；
3. **质量降损**：代码规范合规率达95%+，提测Bug和返工率下降20%~30%；
4. **人力节约**：折算每周节约研发人天，新人上手周期缩短一半；
5. **工程沉淀**：加速老项目治理、组件库和文档沉淀，降低团队知识流失风险。


## 🍎AI 生成的代码谁来 Review？流程是什么？

1. **AI自检**
生成代码后，AI先做自查：校验TS类型、边界状态、代码冗余、潜在Bug、规范合规性。
2. **开发者初审（必做）**
开发人员重点审核：业务逻辑正确性、组件拆分、状态管理、样式兼容性，剔除AI幻觉代码。
3. **工程化强制门禁**
走ESLint、Prettier、TS编译、Git校验，拦截不规范、报错代码。
4. **人工Code Review**
普通业务代码：前端组员互审；
公共组件/重构/复杂逻辑：由资深开发或组长复审。
5. **合并入库+沉淀优化**
合入代码后，把优质代码沉淀为上下文范本，反向约束下次AI生成质量。


## 🍂AI 能帮你做什么？不能帮你做什么？

### 1. AI 能帮你做什么
1. **`重复性编码`**：写样板代码、CRUD 页面、表单弹窗、TS 类型、接口请求、工具函数、基础样式，替代 60%～70% 机械打字工作。

2. **`代码补全与语法生成`**：JS/TS/React/Vue 语法、生命周期、Hooks、工具方法、正则、逻辑片段快速生成。

3. **`问题排查与改错`**：分析控制台报错、打包异常、依赖冲突、样式兼容、简单 Bug 定位并给出修复代码。

4. **`代码重构与优化`**：精简冗余代码、拆分组件、JS 转 TS、统一代码风格、抽离公共逻辑。

5. **`生成文档与注释`**：写接口文档、README、函数注释、业务说明、整理知识点和面试题。

6. **`单元测试、用例生成`**：自动生成单测用例、边界用例，提升测试覆盖率。

7. **`项目初始化与模板搭建`**：快速新建项目、搭建目录结构、路由、状态管理、基础配置。


### 2. AI 不能帮你做什么
1. **`不懂真实业务逻辑`**：没法替代产品理解、业务规则、流程上下文，容易**逻辑幻觉、想当然乱写**。

2. **`无法做架构设计与技术决策`**：技术选型、目录架构、状态管理方案、性能架构，只能人来定，AI 只能辅助落地。

3. **`不能替代业务逻辑把关`**：核心业务流程、权限逻辑、资金/风控等高敏感逻辑，必须人工评审把关。

4. **`无法理解团队隐性规范`**：团队隐性约定、历史技术债、存量逻辑坑，AI 不知道，容易写出不符合项目风格的代码。

5. **`不能做最终质量与上线负责`**：AI 只生成不负责，**代码正确性、稳定性、线上风险**最终责任人还是开发本人。

6. **`复杂跨系统、跨模块全局统筹`**：大型跨业务、跨服务联动逻辑，AI 视角局部化，看不到整体链路。

7. **`不能替代沟通协作`**：需求对接、联调、排期、方案讨论、跨团队协作，AI 完全无法替代。

## 🍂什么时候你选择不用 AI？

1. **`核心业务逻辑设计`**：涉及权限、流程、风控、资金、核心规则，AI 容易逻辑幻觉、想当然脑补业务，必须自己梳理手写。

2. **`技术架构&方案选型`**：整体目录结构、技术栈选型、状态管理、封装设计、跨模块架构，**人做决策，AI 只做落地辅助**，不直接让 AI 定方案。

3. **`底层基础封装&公共核心能力`**：全局拦截器、请求基座、组件库基础抽象、工具底层方法，要求极高严谨性，AI 容易写出冗余、有隐患的代码，不用 AI。

4. **`老项目历史逻辑&隐性规则`**：历史技术债、特殊兼容逻辑、团队隐性约定，AI 读不到隐性上下文，容易改错逻辑、改崩旧功能，不用 AI。

5. **`像素级UI、复杂交互动画`**：精细布局、多端兼容、复杂动效、定制化样式，AI 只能出粗糙版本，精细调校必须手动开发。

6. **`线上紧急故障抢修`**：紧急线上事故、链路止血、根因定位，依赖 AI 容易被错误答案带偏，耽误排障时机，优先自己排查。

7. **`高敏感、高风险代码`**：登录鉴权、权限校验、加密逻辑、支付链路等核心敏感代码，不直接用 AI 生成，避免隐藏漏洞。

涉及**核心业务、架构设计、底层封装、老项目历史逻辑、精细UI交互、线上抢修、敏感链路**，我都不用AI，规避幻觉和业务风险；只在重复样板编码、简单排错场景用AI提效。

## 🍂AI 生成的代码可能有哪些隐蔽的坑？

### 业务逻辑类坑
1. **业务幻觉脑补**：自己瞎补业务规则、默认流程、边界逻辑，和真实产品需求对不上。
2. **边界场景缺失**：只写正常流程，漏掉**加载中、空数据、异常报错、无权限、禁用状态**。
3. **硬编码魔法值**：接口地址、状态码、文案、常量直接写死，不抽常量、不易维护。

### TypeScript 类型坑
1. **隐式 any、类型不严谨**：偷懒不定义完整类型，字段缺失、类型宽泛，后期迭代容易埋雷。
2. **类型结构和后端接口不匹配**：AI 自己虚构字段、嵌套结构，联调才发现对不上。
3. **滥用可选符 ?**：所有字段都加可选，失去类型约束意义。

### 前端交互 & 性能隐蔽坑
1. **重复请求、未做防抖节流**：表单提交、搜索联想频繁触发，无防重、无防抖。
2. **无效渲染、依赖项乱写**：React/Vue 依赖项漏加、乱加，造成死循环或不更新。
3. **事件未销毁、内存泄漏**：定时器、监听事件、订阅回调，组件销毁不清理。
4. **闭包陷阱**：异步回调里捕获旧状态，导致数据错乱。

### 工程化 & 规范坑
1. **不符合项目现有规范**：自创目录结构、命名风格、组件拆分方式，和团队风格割裂。
2. **冗余代码、无效变量**：写了不用的导入、变量、逻辑，堆垃圾代码。
3. **忽略 ESLint/Prettier 规则**：私自用禁用语法、随意缩进、引号风格不统一。

### 兼容性 & 样式坑
1. **样式全局污染**：不做隔离，直接写全局 class，影响其他页面。
2. **浏览器/移动端兼容不足**：只写现代写法，忽略低版本、IOS、安卓兼容问题。
3. **布局自适应不严谨**：固定宽高、不做响应式，不同屏幕错位。

### 依赖 & 安全坑
1. **随意引入多余依赖**：瞎装库、引无用包，增大打包体积、引入未知风险。
2. **安全隐患**：敏感参数直接暴露、未做参数校验、存在注入风险。
3. **API 调用方式老旧**：用废弃语法、过时生命周期、废弃接口写法。

AI 生成后必须做**业务校验、类型校验、性能审查、规范 Review** 才能入库。

## 🍃你如何看待 AI 对前端开发影响？

AI 可以解放重复机械工作、大幅提升研发效率、统一团队代码规范等，但目前不具备业务抽象能力、架构设计能力、质量把控能力等。 所以，AI 不会替代高级前端，但会替代只会搬砖的初级前端。

## 🍃AI 带来的最大风险是什么？

AI 给研发带来**最大的风险不是技术问题，而是人能力退化+代码质量失控**。

第一，**工程师能力惰性退化**
过度依赖 AI 写代码、排 Bug，慢慢丧失底层原理、逻辑拆解、独立排错的能力，变成只会复制粘贴 AI 代码，脱离 AI 就不会开发。

第二，**代码隐性风险泛滥**
AI 容易业务幻觉、漏边界、埋内存泄漏、类型隐患、隐性逻辑漏洞，不经严格 Review 就合入，**长期堆积技术债和线上隐患**。

第三，**团队规范与架构失控**
每个人随意用 AI、各写各的，代码风格、组件设计、技术选型混乱，**破坏原有架构和统一规范**，后期维护成本极高。

第四，**低端岗位内卷淘汰**
只会切图、写 CRUD 页面的初级开发者，价值被 AI 大幅稀释，**岗位竞争加剧、容易被替代**。

## 🍃你觉得未来 3 年前端工程师的核心竞争力是什么？

未来前端拼的不是**敲代码速度**，而是**架构设计、工程化能力、AI管控能力、业务抽象、跨栈全链路解决问题的能力**，从纯执行转向**设计、架构、流程、价值**型工程师。
